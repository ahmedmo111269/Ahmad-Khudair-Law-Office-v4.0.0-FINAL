# Android / PWA — دليل التشغيل والتغليف (v5.13.6)

> هذا المستند يشرح ما تم فعليًا في موجز **Android/PWA Production Readiness**، وكيف يُستخدم التطبيق على الهاتف،
> وما تحقّق فعلًا وما لم يتحقق. المرجع التنفيذي الأحدث هو [CHANGELOG.md](../CHANGELOG.md) و[PROJECT_MAP.md](../PROJECT_MAP.md).

## 1) ما هو التطبيق الآن

| الخاصية | الحالة |
|---|---|
| PWA قابل للتثبيت (Manifest + Service Worker + HTTPS) | ✅ |
| يعمل بلا إنترنت بعد أول تحميل (قشرة + كل ملفات JS/CSS) | ✅ |
| البيانات كلها في IndexedDB على الجهاز نفسه | ✅ (لا سحابة، لا Firebase، لا Supabase، لا Backend) |
| زر الرجوع في Android | ✅ يغلق الطبقة العليا ← يرجع للشاشة السابقة ← يخرج من التطبيق |
| المناطق الآمنة (شريط الحالة/أزرار النظام) | ✅ `env(safe-area-inset-*)` |
| أهداف اللمس ≈44px على الأجهزة اللمسية | ✅ محصورة في `(pointer:coarse)` فلا يتغير سطح المكتب |
| تحديث الإصدار بلا فقد بيانات | ✅ التحديث ينتظر موافقة المستخدم |
| تخزين دائم + تنبيه عند اقتراب امتلاء المساحة | ✅ |

## 2) التثبيت على Android

1. افتح التطبيق في Chrome على الهاتف.
2. الإعدادات ← **📲 تثبيت التطبيق على الهاتف** ← **تثبيت التطبيق الآن**.
3. إن لم يظهر الزر: قائمة المتصفح (⋮) ← «تثبيت التطبيق» أو «إضافة إلى الشاشة الرئيسية».
4. سيظهر تلميح واحد لطيف في الشاشة الرئيسية بعد استخدام فعلي (3 زيارات)، وزر «لاحقًا» يُسكِته نهائيًا.

بعد التثبيت: يفتح من أيقونته بلا شريط عنوان، ويعمل بلا إنترنت.

## 3) كيفية التحديث

- عند نشر نسخة جديدة، يكتشف التطبيق التحديث عند توفر الإنترنت وينزّله في الخلفية.
- تظهر رسالة واحدة فيها زر **«تحديث الآن»**؛ لا يُستبدل الكود تحت يدك أثناء العمل.
- عند القبول: يُفعَّل الإصدار الجديد وتُعاد الصفحة مرة واحدة، وتبقى **IndexedDB والتفضيلات والتخصيصات كما هي**.
- إن لم تقبل، يبقى الإصدار الحالي يعمل بأمان، ويُطبَّق التحديث في جلسة لاحقة عند القبول.

## 4) العمل دون اتصال

- كل الشاشات والبيانات محلية: الملفات، الموكلون، القضايا، الجلسات، التنفيذ، التقارير، البحث، النسخ الاحتياطي.
- البيانات **لا** تدخل Cache Storage: كاش التطبيق للكود والملفات فقط، وبيانات المكتب في IndexedDB.
- عند فقد الاتصال تظهر شارة «⚪ عدم الاتصال» ورسالة عربية واضحة، بلا أخطاء تقنية.
- لا يوجد أي Sync سحابي؛ التبادل بين الأجهزة يبقى عبر حزم ملفات مشفّرة يدويًا (كما كان).

## 5) النسخ الاحتياطي على Android

- الإعدادات/صفحة «النسخ الاحتياطي» ← تنزيل ملف JSON كامل، ثم استيراد/استعادة من الجهاز عند الحاجة.
- على Android يجري التنزيل إلى مجلد التنزيلات، والاستيراد عبر منتقي الملفات؛ الصيغة لم تتغير.

## 6) مسار التغليف (الخطوة التالية، خارج هذا الموجز)

المشروع الآن جاهز للخطوة التالية بلا تعديل كود:

1. **PWABuilder** → حزمة Android (Trusted Web Activity) من رابط الاستضافة، مع أيقونات 192/512 وMaskable الجاهزة والاسم الرسمي من الـmanifest.
2. **Digital Asset Links** (شرط إخفاء شريط العنوان داخل TWA): يحتاج ملف `/.well-known/assetlinks.json` ليطابق بصمة توقيع الحزمة.
   - ملاحظة GitHub Pages: يمرّ الموقع على معالج Jekyll افتراضيًا، وJekyll يستثني المجلدات التي تبدأ بنقطة — لذلك أُضيف ملف `.nojekyll` في جذر المستودع ليُخدَم `/.well-known/…` كما هو. إن استُخدم نطاق خاص أو Cloudflare Pages فالملف يُخدَم مباشرة.
3. لم يُنشأ في هذا الموجز أي مشروع Android أصلي، ولم تُنشر أي حزمة على Google Play (حسب نطاق الموجز).

## 7) حدود التحقق (Declaration of limits)

- **ما تحقّق فعليًا:** Chromium 153 في بيئة البناء بمحاكاة هاتف Android (عرض 412×915، `deviceScaleFactor 2.625`، لمس مفعّل، UA أندرويد) في **21 فحصًا** (`npm run test:android-pwa`) + `Page.getInstallabilityErrors` من بروتوكول DevTools = صفر أخطاء، واختبارات قشرة/تحديث/دون اتصال وضغط تخزين وجدول بيانات RTL وأداء بلا تسريب كاملة. أُضيفت أيضًا لقطتا الشاشة من تشغيل حقيقي بمقاس 360×640 بكثافة 3 (=1080×1920) عبر `npm run screenshots:pwa`.
- **ما لم يتحقق:** جهاز Android حقيقي، وChrome حقيقي على هاتف، وTWA/APK فعلي، ومعاينة الطباعة الأصلية. أي حكم على «التثبيت الحقيقي» يجب أن يُقرأ بوصفه: *المتطلبات التقنية لـManifest وService Worker وInstallability تحققت في حدود ما تسمح به البيئة الحالية*.
