# صفحة الملف — مساحة عمل قانونية «البيانات أولًا» (المرحلة النهائية، 2026-10-11)

إعادة تصميم صفحة الملف الداخلية (`file:ID`) على أربعة مستويات واضحة:

1. **رأس الملف** — هوية القضية والأطراف الأساسية والإجراءات العامة.
2. **شريط تبويبات أفقي** — التنقل الأساسي: أربعة تبويبات ظاهرة + قوائم منسدلة للأقسام الأخرى.
3. **ملخص تنفيذي** — أهم ما يحتاج إليه المحامي فور فتح الملف، وكل عنصر فيه مرتبط بمصدره الأصلي.
4. **مساحة محتوى موحدة** — تعرض القسم المختار وحده ببياناته ووظائفه الحقيقية (تحميل كسول + كاش).

**لا تغيير في Schema أو المخازن أو `APP_VERSION` أو بيانات المستخدم.**
التغيير الوحيد في التخزين: رقم كاش Service Worker (`v6.2.2-files-workspace` ← `v6.2.3-file-data-first-workspace`)
حتى تصل الملفات الجديدة لمن ثبّت التطبيق. `sw.js` لا يمسّ IndexedDB إطلاقًا.

## 1) جرد ما كان موجودًا قبل التعديل (مصدر الحقيقة لكل معلومة)

| التنفيذ | `executions` عبر `executionsForFile`/`executionContextSummary` | شريط التنفيذ في نظرة عامة + مركز التنفيذ `?fileId=` | خدمات التنفيذ |

## 2) شريط التبويبات: أربعة ظاهرة + قوائم منسدلة وظيفية

| الترتيب | العنصر | النوع | الملاحظة |
|---|---|---|---|
| 1 | نظرة عامة | تبويب ظاهر | الافتراضي دائمًا (لا يُخفى: `canHide:false`) |
| 2 | الجلسات | تبويب ظاهر | عدّاد من عدد سجلات الجلسات الحقيقية |
| 3 | الأعمال الإدارية | تبويب ظاهر | |
| 4 | المراحل والإجراءات القضائية | تبويب ظاهر | سابقًا «المراحل والأرقام القضائية» |
| قائمة | **أطراف الملف** (⚖) | قائمة منسدلة | الأطراف والصفات · العقارات والمركبات |
| قائمة | **الأحكام والإعلانات** (⌘) | قائمة منسدلة | الأحكام · المحضرين والإعلانات |
| قائمة | **البيانات والمراجع** (▤) | قائمة منسدلة | الأتعاب والمستندات · الملاحظات · بيانات نوع العمل · بيانات إضافية (قديمة) |
| قائمة | **الارتباطات والمتابعة** (↔) | قائمة منسدلة | العلاقات والملفات المرتبطة · الخط الزمني · سجل النشاط |
| أدوات | ⋯ كل الأقسام · ◎ وضع التركيز · ⚙ تخصيص الصفحة | أدوات عرض ثانوية | في نهاية الشريط، لا في رأس الملف |

- عناصر القوائم **هي أزرار التبويبات نفسها** (`data-tab`) — لا نسخ ولا أزرار شكلية، ودالة التنقل واحدة (`gotoTab`).
- المجموعة النشطة تُعلَّم (`is-active`) ويظهر في زرها **اسم القسم المفتوح** (`ftb-active-name`) فيعرف المحامي موضعه دون فتح القوائم.
- القائمة المفتوحة: النقر خارجها أو Escape أو اختيار عنصر يُغلقها؛ الأسهم ↑↓ وHome/End للتنقل؛ Enter/Space/↓ للفتح؛ Escape يعيد التركيز إلى الزر.
- **منع القطع عند الحواف:** عرض محدود بالمنفذ (`max-width:min(92vw,360px)`) + إزاحة أفقية محسوبة (`placeTabMenu`) عند تجاوز حدود الشاشة يمينًا/يسارًا + حد ارتفاع مع تمرير داخلي.
- **الأقسام المخفية** من «⚙ تخصيص الصفحة» تخرج من الشريط والقوائم، وتبقى في «⋯ كل الأقسام» موسومة **«مخفي»** — لا وظيفة تصبح غير قابلة للوصول.
- **الشاشات الصغيرة:** شبكة متساوية (4 أعمدة) للتبويبات الأساسية وصف للقوائم، مع تسميات قصيرة للشاشات الضيقة (الأسماء الكاملة في `aria-label`/`title`)، وبلا تمرير أفقي.
- **الالتصاق:** الشريط ملتصق أثناء التمرير بإزاحة مقيسة فعليًا (`syncStickyTop`): شريط التنقل ← شريط الصفحة ← الشريط المختصر للهوية ← التبويبات؛ ولا تراكب: طبقات `z` هي (12) التنقل · (10) شريط الصفحة · (9) الشريط المختصر · (8) التبويبات.

## 3) «نظرة عامة»: لوحة متابعة لا نسخة مكررة

**أ. الملخص التنفيذي (4 بطاقات للقراءة والتنقل فقط):**

| البطاقة | المصدر | الإجراءات |
|---|---|---|
| أقرب جلسة قادمة | `hearings` (أول جلسة ≥ اليوم بلا نتيجة) | عرض الجلسة (سجلها) · كل الجلسات · دورة الجلسات |
| آخر عمل إداري مسجل | `procedures` (أحدث سجل بترتيب `actionDate/internalDueDate/createdAt`) | عرض العمل (سجله) · الأعمال |
| المرحلة الحالية | `cases` (`currentStageId`) | فتح بيانات المرحلة · المراحل |
| الجلسة السابقة | `hearings` (أحدث جلسة سابقة) | عرض الجلسة · كل الجلسات |

- بلا بيانات: **حالة فارغة صريحة** («لا توجد جلسات مسجلة لهذا الملف بعد.») بلا أي تاريخ أو رقم أو حالة مُختلقة،
مع زرّ ينقل إلى التبويب المعني.
- ثم قمرة الملف (`fileCockpitHtml`: الخطوة التالية + زر «✓ تم» + الإحصاءات + المرحلة الحالية) وسطر تابع
(آخر نشاط مسجل · متابعات غير مكتملة · الموكل المسجل) من `files.lastActivityAt` والأعمال والأطراف.

**ب. البيانات التفصيلية (قابلة للطي):** «بيانات الدعوى والملف» — حقول الملف كاملة + حقول المرحلة الحالية + حقول نوع العمل،
مع أزرار تعديل الملف/المرحلة/تغيير النوع.

**ج. المسار القضائي:** «المرحلة والتسلسل القضائي» — المراحل بترتيبها المحفوظ مع جلسات/أحكام/أعمال كل مرحلة (قراءة من مصادرها)،
والملفات المرتبطة بعلاقات مسجلة، وشريط إدارة المراحل القائم، وكل عنصر يفتح سجله الأصلي.

**د.** شريط التنفيذ السياقي (`?fileId=`) ولوحة «مهام الملف».

**أُزيل من نظرة عامة (لا نسخ مكررة):** شريط المؤشرات `.fp-metrics` (كان يعيد نفس أرقام القمرة)، وبطاقتا
«الجلسات القادمة» و«الجلسة السابقة» القائمتان (كانتا تعيدان سجل الجلسات)، وبطاقة «ملخص عملي» الجامعة لهما.
كل أرقامها وروابطها موجودة الآن في بطاقات الملخص التنفيذي وفي تبويب الجلسات نفسه — بلا فقدان أي وظيفة.

## 4) منع تكرار البيانات (شرط معماري)

- لا حقل ولا سجل جديد لأي ملخص؛ الملخصات **تُشتق عند العرض** من السجلات الأصلية في `Promise.all` واحد.
- لا كتابة من «نظرة عامة» إطلاقًا: كل إجراء فيها إما `data-open`/`data-open-case` (يفتح السجل الأصلي)،
أو `data-tab-jump` (ينقل إلى تبويبه)، أو `data-hearing-cycle` (نافذة قراءة)، أو تعديل صريح عبر نماذج الملف/المرحلة القائمة.
- البيانات المتكررة عرضًا (مثل عدد الجلسات) تظهر في الشريط كعدّاد للتنقل فقط، وفي القمرة كإحصاء تشغيلي — وكلها مشتقة من المصدر ذاته.
- لا تغيير في المخطط والمخازن ولا في خدمات القراءة/الكتابة ولا في الصلاحيات أو التحقق أو سجل النشاط.

## 7) إصلاحات إضافية اكتُشفت أثناء الاختبار

- **الرابط الصريح `?tab=` كان يُتجاهل عند إعادة فتح الملف نفسه**: الشرط القديم كان يحتفظ بتبويب الجلسة
المرصود للملف متجاهلًا القسم المطلوب من الرابط. الآن الأولوية: `?tab=` الصريح ← آخر تبويب محفوظ لنفس الملف ←
«نظرة عامة»، ويفتح الرابط أقسام القوائم المنسدلة أيضًا ويُعلّم مجموعتها (فحص 25).
- **شارة المرحلة الحالية في رأس الملف**: تُعرض فقط عند وجود مرحلة مسجلة فعلًا (`currentStageId` أو آخر مرحلة)
ودون أي قيمة افتراضية — تكملة لبند «حالة الملف والمرحلة الحالية» في الرأس.

- **زرّ الدبوس كان بلا اسم وصول عند الإنشاء (عيب حقيقي في مكوّن مشترك)**: فحص شجرة الوصول (30) وجد
ثلاثة أزرار `button.collapse-pin` داخل محتوى الملف بلا اسم، وسببها أن المواضع الثلاثة في `js/ui/collapsible.js`
كانت تبني الزر بـ`createElement` وتضبط الاسم فقط عند أول تغيير حالة (`syncCollapsePin`). أُصلح الجذر عبر
