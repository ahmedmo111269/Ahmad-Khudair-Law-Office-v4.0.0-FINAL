# خطة إعادة تنظيم التنقل — بعد خط أساس W0

**الحالة (2026-10-11):** W0 وW1 مكتملان؛ W2 لم يبدأ. **W0** يبقى خط الأساس التاريخي، فلا يُعاد هذا الجرد من الصفر في كل مرحلة. راجع [`RESTRUCTURE-BASELINE.json`](./RESTRUCTURE-BASELINE.json) و[`RESTRUCTURE-NAVIGATION-MAP.md`](./RESTRUCTURE-NAVIGATION-MAP.md) وتقرير التنفيذ في [`RESTRUCTURE-FINAL-REPORT.md`](./RESTRUCTURE-FINAL-REPORT.md).

## مبدأ التنفيذ

تطوير التنقل القائم لا استبداله: الإبقاء على `App.go()` و`RouteHistory` و`NAV_GROUPS` و`PAGES` ومخازن IndexedDB والخدمات والتفضيلات الحالية. لا راوتر ثانٍ، ولا مخزن UI موازٍ، ولا تغيير لمعنى المسارات أو سجل قانوني أو علاقة أو حقل. كل مرحلة لها نطاق واختبارات مقارنة بخط أساس W0؛ الاختبارات العامة لا تُعاد إلا للتحقق من التغييرات التي تمسها، مع تسجيل المجموعة/التاريخ/النتيجة فعلًا.

## W0 — خط الأساس (هذه المرحلة)

**المخرجات:** خريطة المسارات والحالة الداخلية، جرد البيانات والخدمات/التفضيلات، خطة تنفيذ، تقرير الحالة. **النتيجة:** أُنجز الجرد والقياس؛ لم تتغير شيفرة التطبيق أو المخطط. يسجل `docs/RELEASE-AUDIT.json` نتيجة تدقيق الإصدار الحالي التي فشلت، ولا تُعتبر هذه المرحلة إصلاحًا لتلك الفجوات.

## W1 — عقد سجل التنقل والغلاف الأفقي المتجاوب

**الحالة:** مكتمل على الشيفرة والاختبارات بتاريخ 2026-10-11؛ نتائج التنفيذ والحدود مسجلة في التقرير النهائي. لا ترقية IndexedDB ولا تغيير لمعنى بيانات المكتب.

**النطاق:** توحيد *بيانات* التنقل مع إبقاء الراوتر الحالي، ثم تنظيم العرض حسب قياس الجهاز.

1. تطوير `js/ui/nav-model.js` كمصدر وصف واحد للعناصر الحالية (أو امتداد صغير ملاصق له): `routeId`, الاسم، مجموعة العرض، الأيقونة، المسار/alias، ترتيب افتراضي، تصنيف الوجهة، أولوية الهاتف وشارة إن وجدت. لا تحوي الواجهة قواعد قانونية أو دوال أعمال.
2. استخدام سجل التعريفات في `topnav.js` و`nav-customize.js` و`palette.js` ومدخل «كل الأقسام» وشريط الهاتف؛ يبقى `PAGES` مسؤولًا عن ربط معرّف المسار بمعالجه، و`App.go()` عن الانتقال، و`RouteHistory` عن الـhash/الرجوع. توافق صريح لـ`caseNotes`/`quickNotes`، وعدم دمج `execution` بقائمة `executionCenter` أو إسقاط `feePayments` و`sync`.
3. **سطح المكتب/اللوحي:** الاحتفاظ بمجموعات الشريط الحالية الست، بلوحاتها و«المزيد» والتخصيص والسحب والحفظ وإشارة المسار النشط. يمكن تحسين أولوية overflow إذا أثبت اختبار العرض حاجة؛ لا تُحذف مجموعة ولا يتغير ترتيب المستخدم المحفوظ.
4. **الهاتف:** تكييف العرض إلى 4–5 وجهات مباشرة مع «المزيد» (5–6 أزرار إجمالًا وفق حد اللمس والعرض)، مع لوحة «كل الأقسام» ومسار دائم لكل عنصر قائم. مجموعة البداية المقترحة للاختبار: `dashboard`, `actionCenter`, `files`, `clients`, `hearings` ثم `more`; ترتيبها قرار عرض افتراضي قابل للتخصيص لا نقل بيانات. إذا لم تحقق أهداف اللمس/الملصقات عند 320px، ينقص عدد الوجهات الظاهرة ويظل الباقي في «المزيد» بلا حذف.
5. منع التكرار: لا يظهر شريط عالمي مكرر أسفل وفوق الهاتف؛ يعاد استخدام عناصر الغلاف الموجودة، مع إبقاء زر القائمة/«كل الأقسام» متاحًا. تظل إضافة سريعة، Undo، البحث، التذكيرات والملاحظة السريعة إجراءات غلاف مستقلة. يُرفع زر الملاحظة العائم عن الشريط الجديد بمسافة آمنة.
6. الحفاظ على الشارات العاجلة والوجهة النشطة، ومساحات `safe-area-inset-*`، RTL/LTR، أحجام الهدف، لوحة المفاتيح/التركيز، قارئ الشاشة، الثيم الداكن والفاتح والحركة المخفّضة. تبقى الواجهة عربية وهوية المكتب كما هي.

**بوابة W1 — التنفيذ والنتيجة الفعلية:**

- وحّد `NAV_GROUPS` تعريف المسارات، والأسماء، والأيقونات، وكلمات لوحة الأوامر والـalias؛ لوحة الأوامر تُبنى من السجل نفسه. حُفظ `quickNotes` كاسم توافق لـ`caseNotes`، وبقي `execution` منفصلًا عن `executionCenter`، وأُضيفت الوجهة القائمة `feePayments` إلى مجموعة الأتعاب؛ صار سجل التنقل 31 مسارًا (30 سابقًا + هذه الوجهة) مع بقاء `sync` و`executionCenter` ظاهرين في لوحة الأوامر.
- شريط الهاتف يعرض افتراضيًا 5 وجهات أساسية (`dashboard`, `actionCenter`, `files`, `clients`, `hearings`) و«المزيد» بكل الوجهات الأخرى، مع احترام ترتيب/إخفاء تفضيلات التنقل. زر الرأس يحتفظ بلوحة «كل الأقسام». الوصول إلى الصفحات يتم عبر `App.go()` الحالي، دون Router أو مصدر URL جديد.
- `tools/node-tests/run-tests.mjs`: **619/619 PASS**؛ يشمل تغطية المصفوفات والـalias ولوحة الأوامر وترتيب الهاتف، مع اختبار صافي لتزامن `RouteHistory` عند اختيار وجهة وإغلاق مدخل حماية لوحة الهاتف.
- Chromium `tests.html`: **637/637 PASS** بلا أخطاء وحدات/صفحة.
- `tools/node-tests/android-pwa-browser-tests.mjs`: **30/30 checks verified** بمحاكاة Chromium للهاتف، لا جهاز فعلي. شمل اختبار التنقل عند 320/360/390/412/640/768/1024/1280px، أهداف اللمس، Keyboard/Home/End/RTL/Escape، الـMore sheet والرجوع، تغيير hash عبر App.go، والاستمرار Online/Offline/بعد restart وتحديث التطبيق.
- يظل اختبار فتح المفاتيح الثابتة `PAGES` **32/32** من W0 صالحًا لأن W1 لم يغيّر معالجاتها؛ لا يُعامل ذلك كتغطية لكل معرف سجل ديناميكي. لم يُنفذ اختبار على هاتف فعلي، ولم يُعَد تشغيل تدقيق الإصدار/المنصات بعد W1؛ فروق الإصدار/الكاش وتحذير الرابط من W0 ما زالت مفتوحة في `docs/RELEASE-AUDIT.json` والتقرير.
- لم تتغير قاعدة البيانات أو مخططها، ولا ملفات المستخدم/السجلات/العلاقات؛ ولم تُضف ملفات runtime، لذا لا تغيير لـService Worker أو إصدار الكاش.

## W2 — حالة المسار للتبويبات الداخلية والروابط العميقة

1. إصلاح تزامن `file:<id>?tab=<id>` مع hash والحالة المرئية باستخدام واجهة صغيرة على **App/RouteHistory الحاليين** لا History API مستقلًا؛ يجب ألا يؤدي انتقال تبويب ملف إلى فقد نموذج غير محفوظ أو إعادة قراءة الملف كله.
2. تمكين فتح/إعادة تحميل/Back/Forward للتبويبات الداخلية للإعدادات وبطاقة التنفيذ حيث يفيد، مع إبقاء التفضيل القائم بديلًا عندما لا يحدد الرابط التبويب. مرشح ملف الموكل وفلاتر العمل تبقى حالة مرشح وليست مسارات عالمية.
3. إضافة breadcrumbs/سياق صفحة خفيف مشتق من route IDs وروابط العلاقات القائمة فقط عند الحاجة؛ لا `all()` ولا قراءة غير محدودة لملء عنوان المسار. على سجل مستخدم محذوف/غير متاح تظهر حالة صادقة ولا تُنشأ علاقة بديلة.
4. عدم تحويل نطاقات Work Center أو طرق عرضه الـ22 إلى 22 رابطًا على الشريط؛ الاستمرار في استخدام معاملات الرابط الحالية وحالة التفضيل.

**بوابة W2:** اختبارات خاصة back/forward/refresh لكل تبويب مدعوم، وسيناريوهات ملفين مستقلين، إعدادات، تنفيذ، فقد اتصال/إقلاع Offline، حفظ مسودة نموذج، RTL ولوحة المفاتيح. كل تنقل داخلي يختبر `push` أو `replace` بالمقصد الموثق؛ لا ازدواج مدخلات بلا داعٍ.

## W3 — سياق الصفحات ومسارات الوصول بين الكيانات

- الحفاظ على Office Today والرئيسية، Work Center، File Cockpit، ملف الموكل، السجلات والجداول كما هي؛ تُعاد صياغة الوصول وروابط السياق فقط بعد أن تكون الوجهة مسجلة.
- إظهار «أنت هنا» وروابط الوالد/الفرع من العلاقات الأصلية (`fileId`, `caseId`, `clientId`...) دون تكرار الحقول أو تفريغ المحتوى في تبويبات جديدة.
- إبقاء الجلسة/الإجراء/الموعد الأصلي مصدرًا وحيدًا لـWork Center overlays، وإبقاء `Quick Add` يمر عبر الخدمات والنماذج والسياق نفسه.
- التحقق من أسهم الرجوع والإغلاق وفتح السجل والروابط بين الملف والموكل والقضية والخصم والتنفيذ والملاحظة.

## W4 — البحث والأوامر والإضافة السريعة

- توليد **أوامر التنقل** من سجل W1، مع بقاء إجراءات الإضافة والتعديلات السياقية أوامر مستقلة وليست route records.
- تغطية المسارات الموجودة في لوحة الأوامر، بما فيها `executionCenter` و`sync`، مع alias صحيح للملاحظات، دون مضاعفة Quick Add أو مصدر البحث.
- الحفاظ على `Ctrl/Cmd+K`, `Ctrl/Cmd+Shift+N`, السياق الحالي للملف/القضية/الموكل، Undo والطلب الصريح لتأكيد الأعمال المعدِّلة. الاختصارات لا تعمل داخل حقول الكتابة.

## W5 — اختبار التكافؤ والسلامة والأداء

1. إعادة تشغيل مجموعات الاختبار المتأثرة بهذا التغيير، مع أسماء ملفات وأرقام نتائج؛ ثم اختبارات السطح الكامل اللازمة للإطلاق. لا تُحسب قيمة inventory وحدها نجاحًا سلوكيًا.
2. مقارنة عدد route IDs والـaliases والصفحات/الأفعال والحقول والمخازن والعلاقات قبل/بعد. لا يجوز أن ينقص أي منها؛ فتح صفحات أو تغيير تنقل لا يغير سجل IndexedDB.
3. تشغيل fixtures مؤقتة منفصلة لقياسات **1,000** و**50,000** سجل، ومقارنة Work Center بقياس W0 ذي **305,000** سجل. قياس وقت فتح أول صفحة، الأعداد، حجم/عدد القراءات المفهرسة و`getAll`, الذاكرة، الإلغاء/التبديل، والوقت على الهاتف المحاكى. لا تكتب بيانات اصطناعية في قاعدة مستخدم حقيقية.
4. اختبارات PWA/offline: بدء التطبيق، فتح رابط مباشر، التصفح، إضافة محلية عند انقطاع الشبكة، وإعادة التشغيل مع بقاء المخازن والتفضيلات. إذا أضيفت ملفات runtime، أضفها لقائمة `sw.js` ثم تحقق من versioning بالتنسيق المعتمد.
5. تكرار مسارات W0 الحية ذات الصلة: 32 مسارًا ثابتًا، File Cockpit، Work Center، Office Today، الأفعال/العلاقات، تخصيص المستخدم، لوحة المفاتيح، الثيم واللغة.

## W6 — التقرير والتسليم

تحديث `docs/RESTRUCTURE-FINAL-REPORT.md` بالتنفيذ الفعلي ومقارنة قبل/بعد، قائمة الاختبارات الحقيقية وأي غير منفذ، حدود الأداء والجهاز، مخاطر الإصدار/المدقق المفتوحة، وما بقي من عمل. التقرير الحالي يجمع إقفال W0 وW1؛ ولا يعني اكتمال إعادة الهيكلة كلها قبل إنهاء W2–W6.

## معايير القبول العابرة للمراحل

| المعيار | إثبات مطلوب |
|---|---|
| عدم حذف وظيفة أو مسار/حقل/علاقة/صف مستخدم | مقارنات route/schema/store/API قبل/بعد واختبار استعمال وظيفي؛ aliases لا تختفي |
| مصدر حقيقة واحد | كل زر يتبع route IDs الحالية وApp.go؛ عمليات CRUD عبر الخدمات وRepository؛ Work Center لا ينسخ السجل |
| لا تغيير لمعنى العمل القانوني/المالي | التغيير واجهة فقط؛ لا حسابات أو قواعد قانونية جديدة ولا بيانات مفترضة |
| Offline-first/PWA | اختبار فعلي بلا شبكة، reload/restart، cache graph وتحديث لا يمس البيانات |
| تفضيلات المستخدم | عدم مسح/تغيير صيغة `ui:topnav-config`, التخصيص، الثيم، الطي، grid/file/work/execution؛ إضافة قيم اختيارية فقط |
| RTL وإمكانية الوصول | اسم/دور وحالة Active مفهومة، لوحة مفاتيح وتركيز مرئي، Esc وBack، أهداف لمسية، لا قص/تداخل |
| الروابط والرجوع | deep-link وrefresh وback/forward للمسارات والحالات التي تقبلها؛ فتح سجل ديناميكي يبرز مجموعته |
| الأداء | صفحات وفهارس محددة الحجم؛ لا `getAll` شامل غير مضبوط، لا جلب متكرر لمجرد تبديل tab/view |
| الاختبارات | نتائج مؤرخة ودقيقة، مع بيان device emulation والرسائل البيئية والإخفاقات؛ لا نجاحات تاريخية منسوخة كأنها حديثة |

## المخاطر والحواجز

- **إصدارات مختلفة ظاهريًا:** app/changelog/cache هي 5.17.0 / 6.2.1 / 6.2.4، والمدقق يقارنها بطريقة تفشل. تُحسم سياسة الرقم قبل تعديل changelog أو Service Worker.
- **سياسة الشبكة:** رابط `wa.me` يُطلق بنقرة المستخدم؛ لا يُحذف لتصفير فحص ساكن.
- **الـdeep-link الجزئي:** دعم `?tab=` على الملف قراءة أولية فقط؛ أي حل يستبدل DOM عند اختيار التبويب قد يخسر مسودة نموذج. يجب أن يحافظ التنفيذ على DOM/مدخلات المستخدم.
- **تعقيد الرؤوس:** في W0، Chromium 390px لم يُظهر تراكب رأس الهاتف كما يذكر مستند محدوديات قديم؛ يلزم تثبيت اختبار مقاس قبل تحديث ذلك المستند.
- **ضخامة البيانات:** هناك فهرسة/ترقيم مؤشر على القوائم، وقياس W0 Work Center عند 305k فقط. لا يثبت ذلك أداء كل تحليل أو هاتف.
- **الاستعادة والمسح:** في الإعدادات توجد أفعال صريحة لمسح بيانات/استعادة نسخة. نطاق W1/W2 تنقل؛ لا تنقل هذه الأفعال إلى زر قريب من More/Quick Add ولا تغيّر التأكيد أو معنى العملية.

## التراجع الآمن

قبل أي مرحلة، يسجل `git diff` ومسارات العمل ونتائج الاختبارات. تغييرات W1 لا تحتاج هجرة قاعدة؛ إن أضيفت مفاتيح تفضيل جديدة فتكون اختيارية وتترك المفاتيح القديمة قابلة للقراءة. لا يُمسح تخصيص قديم ولا يعاد تسمية route ID بلا alias دائم. تراجع الواجهة يعيد الشيفرة فقط، ولا يتطلب حذف سجل المستخدم أو إعادة تهيئة IndexedDB. أي تعديل مخطط لاحق يحتاج سببًا مستقلًا، نسخة احتياطية، ترحيلًا إضافيًا واختبارات ترقية/استعادة، وليس مطلوبًا في W1.
