# Release Candidate Checklist — v4.0.0-RC2

## نطاق المراجعة
هذه المراجعة تتعامل مع المشروع كتطبيق إدارة دورة الملفات القانونية محليًا، وليس كتطبيق حساب مواعيد أو حاسبات قانونية.

## فحوصات آلية منفذة
- [x] فحص صياغة JavaScript لجميع ملفات `js/**/*.js` باستخدام `node --check`.
- [x] البحث عن `location.reload()` و`location.href` و`window.location` و`document.location` في كود التطبيق.
- [x] البحث عن `getAll()` داخل طبقة التطبيق؛ الاستخدام المتبقي محصور في `Repository.all()` كمسار توافق صريح ومحدود.
- [x] مراجعة وجود اختبارات المتصفح الأساسية.
- [x] إضافة دعم `toThrow` و`not.toThrow` إلى مشغل الاختبارات حتى تكون اختبارات التزامن قابلة للتقييم فعليًا.

## فحوصات معمارية
- [x] IDs نصية محلية.
- [x] قاعدة بيانات نشطة واحدة لكل نافذة.
- [x] Registry منفصل عن قواعد IndexedDB.
- [x] فتح القاعدة الجديدة قبل إغلاق القديمة عند التبديل.
- [x] Soft Delete / Archive منفصلان.
- [x] File منفصل مفاهيميًا عن Case.
- [x] علاقات الموكلين عبر Junction Stores.
- [x] Cursor Pagination للقوائم الأساسية.
- [x] Indexed autocomplete للعلاقات.
- [x] Transaction boundaries للعمليات المركبة.
- [x] optimistic concurrency عبر `version` حيث يدعمها مسار الحفظ.
- [x] Backup مع manifest وSHA-256 عند توفر Web Crypto.
- [x] Database Doctor / Integrity / Repair كمسارات منفصلة.
- [x] BroadcastChannel لعزل سياق قواعد البيانات بين النوافذ.

## فحوصات UX المطلوبة قبل الإنتاج الفعلي
- [ ] اختبار بصري يدوي على هاتف حقيقي.
- [ ] اختبار بصري على سطح مكتب بعرض صغير ومتوسط وكبير.
- [ ] اختبار كل زر رجوع/إغلاق في النماذج والسجلات.
- [ ] اختبار الفرز والتصفية المركبة على بيانات فعلية كبيرة.
- [ ] اختبار الطباعة والتصدير والمشاركة على المتصفحات المستهدفة.
- [ ] اختبار تبديل قواعد البيانات في نافذتين في الوقت نفسه.
- [ ] اختبار الاستعادة على نسخة احتياطية كبيرة على جهاز الإنتاج المستهدف.

## معيار قرار الإنتاج
`RC1` ليس شهادة بأن التطبيق مناسب بلا اختبار ميداني. أي مشكلة حرجة في البيانات، المعاملات، الاستعادة، العزل بين قواعد البيانات، أو فقدان البيانات تمنع اعتبار الإصدار إنتاجيًا حتى تُغلق.
