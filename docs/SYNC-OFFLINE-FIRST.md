# المزامنة والعمل Offline-First

## مصدر البيانات وسلامة الترحيل

- تبقى قاعدة العمل الوحيدة لكل جهاز هي IndexedDB النشطة للمكتب. الهاتف والكمبيوتر قواعد مستقلة؛ لا تجعلهم Service Worker أو `localStorage` أو `BroadcastChannel` نسخة واحدة.
- البنية الحالية `SCHEMA_VERSION=18`. تستخدم طبقة المزامنة المخازن الحالية `syncChanges` و`syncState` و`syncConflicts` و`syncPeers` داخل قاعدة المكتب. هذا التغيير **لا يرفع المخطط ولا يمسح/يعيد إنشاء قاعدة**.
- `DatabaseContext` يلتقط تغييرات مخازن البيانات في معاملة IndexedDB نفسها. الحذف المنطقي/Tombstones ومتجهات السببية وسجل التغييرات هي أساس المزامنة؛ لا تُحسم التعديلات المتزامنة بآخر وقت كتابة.
- إنشاء خط الأساس التاريخي على دفعات لا يبدأ إلا بعد موافقة المستخدم وتنزيل نسخة الأمان في خطوة الإعداد الأولى. يمكن استئنافه بأمان إذا انقطع؛ Change IDs تمنع تكرار التغييرات.
- كل جهاز يحتفظ بقاعدة محلية صالحة للعمل دون اتصال. لا يعمل ناقل الخادم أثناء Offline؛ تظل الكتابات محلية وتُرسل بعد عودة الشبكة إذا فعّل المستخدم النقل التلقائي.

## خيار 1: نقل حزمة مشفرة يدويًا (Offline)

1. افتح «المزامنة»، واختر الحزمة الواردة المشفرة إن وجدت.
2. أدخل عبارة مشتركة قوية (12 حرفًا على الأقل)، وشاركها بقناة منفصلة وآمنة.
3. راجع ملخص الجهاز والتغييرات والتعارضات ثم أكّد. الإلغاء لا ينشئ خط أساس ولا يطبق تغييرات.
4. ينزّل التطبيق نسخة أمان كاملة بصيغة JSON غير مشفرة، ثم يجهز خط الأساس ويطبق التغييرات على دفعات وينشئ حزمة رد.
5. انقل حزمة الرد إلى الجهاز الآخر، وكرر حتى تكتمل الدفعات.

حزم الملفات تستخدم AES-256-GCM ومفتاحًا مشتقًا من العبارة بواسطة PBKDF2-SHA-256 (310,000 دورة) مع salt وIV عشوائيين. لا تُقبل الحزم النصية غير المشفرة. **النسخة الاحتياطية JSON غير مشفرة**؛ احفظها في موقع موثوق ولا ترسلها عبر قناة عامة.

## خيار 2: خادم relay ذاتي الاستضافة (اختياري)

هذا النقل يحقق اتصالًا فعليًا بين جهازين مستقلين، لكنه يحتاج إلى خادم HTTPS تستطيع الأجهزة الوصول إليه. لا توجد خدمة مُدارة أو مزود خارجي مضمّن، ولا يُرفع شيء تلقائيًا قبل إعداد مسؤول الخادم ثم موافقة المستخدم الصريحة. الاستضافة والبنية التحتية ومسؤولية النسخ والاحتفاظ تقع على المكتب.

### إعداد الخادم

الملف `server/sync_relay.py` خادم Python قياسي (لا تبعيات pip) مع SQLite. شغّله على خادم المكتب أو خادم موثوق خلف reverse proxy يدعم TLS؛ اترك خدمة Python على `127.0.0.1` ولا تعرض منفذها مباشرة للإنترنت.

1. أنشئ معرّف مساحة خاصًا بالمكتب ورمز وصول عشوائيًا طويلًا لكل جهاز. مثال توليد محلي (لا ترسل الأسرار في المحادثات):
   ```sh
   python3 -c 'import secrets; print(secrets.token_urlsafe(24).rstrip("="))'  # workspace ID
   python3 -c 'import secrets; print(secrets.token_urlsafe(48).rstrip("="))'  # bearer token
   ```
2. اضبط متغير بيئة `AKL_SYNC_TOKENS` ككائن JSON يربط workspace ID بمصفوفة رموز الأجهزة، مثل البنية التالية مع استبدال النصوص محليًا:
   ```json
   {"WORKSPACE_ID_HERE":["DEVICE_TOKEN_A_HERE","DEVICE_TOKEN_B_HERE"]}
   ```
3. اضبط `AKL_SYNC_DB` إلى مسار دائم خاص غير منشور على الويب، و`AKL_SYNC_ALLOWED_ORIGINS` إلى أصل التطبيق الدقيق (scheme + host + port بلا مسار)، ثم شغّل. الخادم يرفض الإقلاع إذا غاب هذا الإعداد أو كان `*`؛ لا تستخدم wildcard CORS في الإنتاج:
   ```sh
   export AKL_SYNC_HOST=127.0.0.1
   export AKL_SYNC_PORT=8787
   export AKL_SYNC_DB=/var/lib/akl-sync/relay.sqlite3
   export AKL_SYNC_ALLOWED_ORIGINS=https://app.example.org
   export AKL_SYNC_TOKENS='{"WORKSPACE_ID_HERE":["DEVICE_TOKEN_A_HERE","DEVICE_TOKEN_B_HERE"]}'
   python3 server/sync_relay.py
   ```
4. وجّه نطاق HTTPS عبر reverse proxy إلى `http://127.0.0.1:8787`، واسمح بأجسام حتى 9 MiB وطلبات `GET, POST, OPTIONS` ورؤوس `Authorization, Content-Type, Accept`. اضبط CORS على نطاق التطبيق المحدد، وفعّل TLS/تجديد الشهادة، وجدارًا ناريًا وحدّث النظام دوريًا.
5. احتفظ بملف SQLite على وسيط دائم وخذ نسخة خادم احتياطية. الخدمة لا توفر نقطة حذف/تنظيف؛ الحزم تُحتفظ بها لتتمكن الأجهزة الجديدة من أخذ التاريخ كاملًا. راقب المساحة ولا تحذف صفوفًا يدويًا قبل التأكد من خطة ترحيل لكل الأجهزة.

### ربط الأجهزة

- في كل جهاز افتح «المزامنة»، وأدخل عنوان HTTPS، ومعرّف workspace نفسه، ورمز ذلك الجهاز، وعبارة التشفير المشتركة نفسها. اختبر الاتصال والتشفير ثم احفظ.
- أول مزامنة لخادم تتطلب تنزيل نسخة الأمان وخط أساس محلي. زر «مزامنة الخادم الآن» ينفذ ذلك قبل النقل. على جهاز جديد، كرر الإعداد ثم المزامنة لتنزيل الحزم التاريخية.
- يمكن اختيار «مزامنة تلقائية» صراحةً. تعمل عند الإقلاع/تغير بيانات المكتب/عودة الإنترنت/إظهار الصفحة، مع فحص دوري أثناء بقاء التطبيق مفتوحًا. يلزم فتح التطبيق أو إيقاظه ليجري المتصفح نقلًا دوريًا؛ لا توجد خدمة دفع تعمل والتطبيق مغلق.
- المزامنة اليدوية عبر الخادم تنزّل نسخة أمان قبل كل دورة. الخيار التلقائي لا يفرض تنزيل ملف مع كل دورة خلفية؛ يعتمد على سجل تغيير سببي ومعالجة تعارض آمنة، لذلك احتفظ بنسخ احتياطية مستقلة منتظمة.
- «تعطيل مؤقت» يوقف النقل ولا يمس بيانات المكتب ولا يمسح الأسرار المحلية. «تعطيل وحذف الأسرار المحلية» يحذف فقط رمز ومفتاح الاتصال على هذا الجهاز؛ لا يحذف قاعدة المكتب أو حزم الخادم.

### ما الذي يراه الخادم؟

الخادم يخزّن غلاف AES-GCM المشفر فقط، مع workspace ID وpackage ID عشوائي وcursor/وقت الإنشاء. لا يتلقى العبارة المشتركة أو CryptoKey أو أسماء الأجهزة أو سجلّات المكتب المفكوكة. محتوى الحزم بما فيه اسم الجهاز ومتجهات التغيير مشفر. رمز الوصول ومفتاح AES غير القابل للاستخراج يُحفظان محليًا في IndexedDB (مخزن محلي مستقل للأسرار)، ولا ينسخ التطبيق الأسرار إلى الحزمة أو `localStorage`.

عبارة التشفير هي جذر الثقة المشترك للأجهزة في workspace. لا يمكن لخادم relay معرفة اختلافها؛ اختبار الاتصال يفك أول حزمة موجودة إن وجدت للتحقق. إذا كانت المساحة خالية، لن يتأكد الاختبار من العبارة حتى تصل أول حزمة. حافظ على العبارة خارج الخادم وقناة التبادل. فقدانها يمنع فك الحزم القديمة، لكنه لا يمس بيانات الأجهزة المحلية.

الخادم لا ينفذ دمجًا ولا يقرر التعارض. كل جهاز ينزّل cursors جديدة، ويفك التشفير محليًا، ثم يستخدم `sync-engine` الذي يحتفظ بالقيمتين المتزامنتين للمراجعة/الدمج اليدوي. **لا يُستخدم Last Write Wins**. تظل تغييرات الجهاز المحلي محفوظة عند تعارض أو خطأ شبكة، ويمكن إعادة المحاولة بأمان.

## التخصيص وتحديث PWA

- التخصيص وإخفاء الحقول العرضية وترتيب الأقسام تفضيلات واجهة فقط؛ لا تحذف السجلات ولا تعطل إجراءاتها. الحقول الفارغة في صفحات السجلات متاحة من مخصص البيانات ومخفية افتراضيًا. جداول DataGrid تحتفظ بإعدادات الأعمدة الخاصة بها.
- زر «التحقق من التحديث» يفحص ملفات Service Worker ويعرض النتيجة. تحديث التطبيق لا يزامن قواعد الأجهزة ولا يمس IndexedDB؛ لا يحدث التفعيل/إعادة التحميل إلا بقرار المستخدم.
- `NetworkStatusService` يميز Online/Offline عن حالة المزامنة. `BroadcastChannel` للإشعار بين النوافذ في الجهاز نفسه فقط، وليس بديلًا عن relay أو نقل الملفات.
- Service Worker يخزن Application Shell والملفات الثابتة فقط؛ لا يخزن بيانات المكتب أو استجابات relay في Cache Storage.

## الحماية والحدود

- يلزم HTTPS على كل عنوان غير localhost. عناوين HTTP العامة مرفوضة من التطبيق. إعداد CORS/النطاقات والرموز مسؤولية مشغّل الخادم؛ رمز bearer يسمح بالوصول إلى الحزم المشفرة لمساحة العمل.
- SQLite تحتوي النص المشفر فقط، لكن ينبغي تقييد صلاحيات ملفها وحمايته والنسخ منه وتأمين الجهاز المضيف وسجلات proxy. لا تسجل Authorization أو أجسام الطلبات.
- لا يوجد نقل أثناء إغلاق التطبيق أو Offline. لا يُزامن بين الأجهزة بلا وسيط مشترك (خادم المكتب أو ملفات يدوية).
- حزم محرك المزامنة حتى 500 تغيير/نحو 6 MiB في الدفعة. خادم relay يحدد جسم الطلب بـ 9 MiB وصفحات محدودة؛ إذا ظهر حد حجم أنشئ دفعة أصغر أو ارفع الحد بعد تقييم موارد الخادم.
- لا تحذف قاعدة بيانات موجودة عند ترقية التطبيق؛ ترقية المخطط الحالية إضافية، ولا توجد migration لهذا التغيير.

## التحقق

- `cd tools/node-tests && npm test` — مجموعات IndexedDB والمزامنة السببية والتعارضات والتشفير وعميل relay والحقول/layout.
- `python3 -m unittest discover -s server -p 'test_*.py'` — API relay، المصادقة، CORS، التشفير المعتم، idempotency، pagination، والتحقق من غلاف الحزم.
- `cd tools/node-tests && npm run test:offline-sync-browser` — Chromium لتثبيت Service Worker والعمل Offline وموافقة المزامنة اليدوية.
- `cd tools/node-tests && npm run test:relay-live-browser` — Chromium مع خادم Python/SQLite حي للتحقق من CORS والرموز والتشفير وتبادل بيانات فعلية بين IndexedDB مستقلين.
