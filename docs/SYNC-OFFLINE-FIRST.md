# المزامنة والعمل Offline-First

## مصدر البيانات

- قاعدة العمل الوحيدة هي IndexedDB النشطة للمكتب؛ لا تنشأ قاعدة ثانية أو نسخة نشاط منفصلة.
- ترقية المخطط إلى `SCHEMA_VERSION=16` تضيف `syncChanges` و`syncState` و`syncConflicts` و`syncPeers` داخل قاعدة المكتب نفسها. سجل النشاط يستخدم `activityLog` الحالي.
- `DatabaseContext` يلتقط تغييرات مخازن البيانات في معاملة IndexedDB نفسها. الحذف الفيزيائي يتحول إلى Tombstone (`isDeleted`) كي لا يعيد جهاز آخر السجل المحذوف.
- إنشاء خط أساس البيانات التاريخية يتم على دفعات بعد موافقة المستخدم والنسخة الاحتياطية، وليس عند فتح التطبيق. أثناء الاستيراد، تتقدم مؤشرات `Change ID` ومتجهات الأجهزة في معاملات صغيرة قابلة للاستئناف.
- علامات التغيير المطبّق محليًا تمنع فرع تعارض وارد لم يُعتمد من أن يصبح «الرأس المحلي» ويستبدل قيمة محفوظة لاحقًا.

## نقل حزمة بين جهازين

وسيلة النقل الحالية ملف يدوي، وتعمل Offline. الإجراء على كل جهاز:

1. افتح «المزامنة»، واختر الحزمة الواردة المشفرة إن وجدت.
2. أدخل كلمة المرور المشتركة (12 حرفًا على الأقل). لا تحفظها الصفحة؛ أرسلها إلى الجهاز الآخر بقناة آمنة منفصلة عن ملف الحزمة.
3. راجع ملخص الجهاز والتغييرات والتعارضات، ثم اضغط «تأكيد المزامنة». الإلغاء لا ينشئ خط أساس أو يطبق تغييرات.
4. بعد التأكيد ينزّل التطبيق نسخة أمان عبر نظام Backup الحالي، ثم يجهز خط الأساس ويطبق التغييرات على دفعات وينشئ حزمة رد.
5. انقل حزمة الرد إلى الجهاز الآخر. إذا ظهرت رسالة بوجود دفعة إضافية، كرر تبادل الحزم حتى يكتمل تبادل التغييرات.

حزم النقل تستخدم `AES-256-GCM` مع مفتاح مشتق من كلمة المرور بواسطة `PBKDF2-HMAC-SHA-256` (310,000 دورة)، وملح وIV عشوائيين. لا تقبل طبقة النقل ملفات المزامنة النصية غير المشفرة. تغيير كلمة المرور يتطلب استخدام كلمة المرور نفسها لفك الملف الوارد ثم اختيارها/مشاركتها للدورة التالية.

عند التعارض لا يُستخدم Last Write Wins: تحتفظ قاعدة التعارض بالقيمتين والمتجهين الأصليين. يختار المستخدم المحلي أو البعيد أو دمجًا يدويًا، ويُسجل الاختيار كتغيير جديد؛ تظل سجلات التعارض المحسومة/المتجاوزة محفوظة للتدقيق.

## الاتصال وPWA

- `NetworkStatusService` للاتصال فقط، وحالة المزامنة منفصلة عنه. عودة الاتصال تعرض إشعارًا وزرًا يدويًا ولا تبدأ مزامنة.
- `OnlineCapabilityRegistry` يميز القدرات المحلية عن الخدمات الاختيارية التي تحتاج الإنترنت. القراءة والكتابة والبحث والتقارير ومركز العمل والطباعة والنسخ والاستعادة محلية.
- Service Worker يخزن Application Shell والملفات الثابتة فقط؛ لا يخزن بيانات المكتب أو استجابات API في Cache Storage.

## الحماية والحدود

- ملف المزامنة المنقول مشفر، لكن نظام النسخ الاحتياطي الحالي يصدر JSON غير مشفر. النسخة الاحتياطية السابقة للمزامنة تُحفظ في مجلد التنزيلات؛ احمها ولا تشاركها كملف مكشوف.
- كلمة المرور ليست قابلة للاستعادة من التطبيق. فقدانها يعني تعذر فك الحزمة، ولا يغيّر ذلك قاعدة البيانات المحلية.
- لا يوجد في هذا الإصدار خادم مزامنة، Google Drive أو نقل تلقائي/لحظي؛ تبادل الملفات يدوي. يمكن إضافة ناقل جديد عبر `SyncTransportAdapter` دون ربط مزود الإنترنت بقاعدة العمل.
- حد الملف الوارد 12 MiB؛ التصدير ينشئ دفعات لا تتجاوز عادةً 500 تغيير أو 6 MiB. تُعاد المحاولة بأمان باستخدام Change ID عند الانقطاع.
- لا تحذف قاعدة بيانات موجودة عند الترقية؛ ترقية المخطط إضافية، والاستعادة تستخدم مسار Backup الحالي.

## التحقق

- `cd tools/node-tests && npm test` — اختبارات IndexedDB/المزامنة والتعارض وTombstones والانقطاع/الاستئناف والتشفير.
- `cd tools/node-tests && npm run test:offline-sync-browser` — تحقق Chromium من تثبيت Service Worker، إعادة التحميل والعمل Offline، البحث، Backup/Restore، عدم المزامنة عند عودة الاتصال، الموافقة/الإلغاء، وتصدير الحزمة المشفرة.
