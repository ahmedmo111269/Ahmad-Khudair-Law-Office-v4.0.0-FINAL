# ADR-016 — Database Switching & Multi-Tab Context

## القرار

- لكل نافذة سياق قاعدة بيانات مستقل `DatabaseContext` يحمل `profileId` و`session token`.
- تبديل قاعدة البيانات يفتح السياق الجديد أولًا، ثم يغلق السياق السابق؛ فشل الفتح لا يعطل القاعدة الحالية.
- `BroadcastChannel` يستخدم لمزامنة أحداث تبديل القاعدة والترقية والإغلاق بين النوافذ، مع `sourceId` لمنع معالجة الحدث الذي أرسلته النافذة نفسها.
- `localStorage` Registry هو سجل السياقات؛ حدث `storage` يعيد تحميل السجل عند تغيره خارجيًا.
- لا يعتبر `BroadcastChannel` قفلًا موزعًا ولا يمنح ملكية حصرية للقاعدة.
- لا يسمح السياق القديم بالكتابة بعد إغلاقه؛ طبقة Repository تعتمد على `ctx.assert()`.

## السبب

منع اختلاط بيانات قاعدتين عند تبديل السياق، وتقليل أثر فشل الفتح أو الترقية، والتعامل مع تعدد النوافذ دون افتراض وجود distributed lock.

## الحدود

التزامن بين النوافذ advisory فقط. IndexedDB تظل مسؤولة عن تسلسل عمليات الكتابة، بينما يحتاج أي نظام locking مستقبلي إلى تصميم مستقل واختبارات منافسة.
