# ADR-017 — Index & Query Optimization

## القرار

تُضاف Indexes مركبة فقط عندما يطابق ترتيب مفاتيحها Query Pattern فعليًا، خصوصًا علاقات الكيانات وفرز الأحداث داخل العلاقة.

## القواعد

- الاستعلامات الزمنية العامة تستخدم الفهرس الزمني البسيط.
- استعلامات العلاقة مع ترتيب زمني تستخدم Compound Index مثل `caseId_hearingDate` أو `fileId_date`.
- Junctions تحصل على فهرس عكسي عندما نحتاج الوصول من الطرف الثاني.
- `Repository.byIndex()` يستخدم Cursor محدودًا بدل `getAll()` حتى مع وجود حد.
- لا تُضاف Indexes لمجرد توقع استخدام مستقبلي؛ كل Index يجب أن يرتبط بـ Query Pattern موثق.

## السبب

IndexedDB يخزن الفهارس ويحدّثها مع عمليات الكتابة؛ لذلك زيادة الفهارس لها تكلفة في التخزين والكتابة والترقية. الهدف هو تحقيق توازن بين سرعة القراءة وتكلفة المحافظة على الفهارس.
