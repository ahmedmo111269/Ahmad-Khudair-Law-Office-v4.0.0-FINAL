# تدقيق التصميم وخط الأساس — «الديوان»

> الحالة: **T0 جزئي — تدقيق ساكن للمصدر فقط**. لم تُلتقط لقطات تشغيلية ولم يُشغّل التطبيق داخل متصفح في هذه الجلسة؛ لذلك لا تُعامل الملاحظات البصرية المنقولة في الطلب كحقائق مقاسة. لا يبدأ أي تعديل واسع للواجهة قبل إكمال فحص التشغيل وخط الأساس.

## 2. ملاحظات معمارية مؤكدة من المصدر

1. `page-layout.js` يحتوي بالفعل على إدارة ترتيب الأقسام وإظهارها وإخفائها، ويشير صراحة إلى حفظها عبر `DisplayPreferences (ui:display-prefs)`. توجد كذلك دوال لترتيب الأقسام وإعادة ضبط تفضيلات الصفحة وترحيل مفاتيح ترتيب قديمة؛ لذلك لا مبرر لإنشاء نظام تخصيص موازٍ.
2. `datagrid.js` يتضمن شريط أدوات للجدول، وطيًّا لعوامل التصفية، وحفظ إعدادات العرض/الأعمدة/الفرز/الفلاتر، واختيار الصفوف. يجب تتبع أحداث النقر والتحديد الجماعي قبل أي تغيير في سلوك الصف أو نقل الأدوات.
3. `list-page.js` يحتوي مدخل «تخصيص الصفحة» ومدخل «إجراءات الصف»، وزر إضافة سياقيًا، كما يعرّف قسمًا بعنوان «عوامل التصفية والفترات». وجودها في المصدر لا يثبت أنها تكرر وظيفة لوحة أخرى.
4. `file-page.js` يعرف تبويبات منها «نظرة عامة» و«الجلسات» و«الأعمال الإدارية»، ويذكر أن الملخص التنفيذي يُبنى من مصادره الأصلية. توجد عبارة «لا توجد خطوة مجدولة» في مسار عرض الخطوة التالية؛ يلزم تتبع شروطها وبيانات الاختبار قبل تعديلها.
5. `client-file.js` يتضمن زر تخصيص الصفحة وزر تعديل ملف الموكل. لا يُدمجان قبل التحقق من اختلاف وظيفة كل منهما.
6. `index.html` يحمّل 26 ملف CSS بالترتيب أعلاه؛ يجب مراعاة هذا الترتيب عند تقييم التعارضات والأولوية.

## 3. العناصر مجهولة الوظيفة

| العنصر | النتيجة الحالية | الإجراء الآمن |
|---|---|---|
| زر X | لم يثبت معناه من مراجعة المقتطفات وحدها | تتبع مستمع الحدث والموضع في DOM قبل التعديل |
| سهم → في رأس الصفحة | غير محسوم | تتبع معالج الحدث وحالة التنقل |
| زر «طي» العلوي | غير محسوم | تتبع نطاق الطي والمفاتيح المحفوظة |
| «إجراءات الصف» | مدخل لتخصيص إجراءات الصف ظاهر في `list-page.js` | لا يُحذف؛ تتبع كامل لحفظ التفضيل وتطبيقه |
| شريحة «الأقسام والجداول» | لم يُحسم سلوكها | تتبع مصدر الإنشاء ومعالج التفاعل |
| «قاعدة المكتب الرئيسية» | لم يُحسم إن كانت حالة اتصال أو ملف تخزين أو وصفًا | إبقاؤها حتى يتحدد معناها |
| «التحقق من التحديث» | لم يُحسم نطاق التحقق وآثاره | تتبع الحدث والخدمات التي يستدعيها |
| أيقونة الثيم | آلية الثيم لم تُراجع بالكامل | لا تعديل للتفضيلات قبل تتبع آلية الاختيار والحفظ |
| «ترتيب الصفحة» / «تخصيص الصفحة» | لا يكفي تشابه الاسم لإثبات تطابق الوظيفة | توثيق جميع المداخل ومعرّفات التفضيلات قبل الدمج |

## 4. حالة O1–O16

التصنيف هنا يميز بين **ثبوت وجود بنية في المصدر** وثبوت المشكلة البصرية. لم تُقَس ارتفاعات ولا عدد صفوف في متصفح.

| الرمز | التصنيف الحالي | الدليل/ما ينقص |
|---|---|---|
| O1 | غير مؤكدة | يلزم قياس رأس الصفحة وأشرطة الأدوات وأول صف عند 1024×651 |
| O2 | غير مؤكدة | يلزم قياس قائمة الموكلين عند 1024×660 |
| O3 | غير مؤكدة | زر إضافة موجود في القائمة؛ يلزم جرد بقية المداخل ومقارنة آثارها |
| O4 | غير مؤكدة | مداخل التخصيص موجودة؛ يلزم تتبعها إلى الدوال والتفضيلات ذاتها أو المختلفة |
| O5 | غير مؤكدة | قسم الفلاتر موجود؛ لم يثبت أن اللوحتين تتحكمان في نفس الحالة |
| O6 | غير مؤكدة | لا يمكن إثبات التكرار المرئي من النصوص البرمجية وحدها |
| O7 | غير مؤكدة | يلزم فحص تعريفات الأعمدة وأحداث الصف والتحديد الجماعي |
| O8 | غير مؤكدة | يوجد نظام طي وتخصيص؛ يلزم فحص DOM المرئي في وضع القراءة والتخصيص |
| O9 | غير مؤكدة | المصدر يحتوي ملخصًا تنفيذيًا؛ يلزم ربط كل عداد/حالة ببيانات فعلية وفحص الواجهة |
| O10 | غير مؤكدة | توجد متغيرات كثيرة في `themes.css`؛ لم يُجرَ تدقيق شامل للألوان والتباين المرئي |
| O11 | غير مؤكدة | يلزم عرض صفحة الموكل بعرض هاتف وقياس مجموعات الحقول |
| O12 | غير مؤكدة | لم يُثبت شرط إظهار «عرض محدود» ولا تحقق الاقتطاع الفعلي |
| O13 | غير مؤكدة | يلزم فحص إعدادات الأعمدة وقواعد القص والتفاف الاسم والرقم القومي |
| O14 | غير مؤكدة | توجد عبارة «لا توجد خطوة مجدولة»؛ لم تُثبت حالة التناقض ولا شروطها كاملة |
| O15 | **BLOCKED** | لا يتاح في هذه الجلسة جهاز/متصفح فعلي موثق لاختبار تداخل الزر العائم والشريط السفلي |
| O16 | غير مؤكدة | يلزم قياس امتلاء عمود الخصم والتمرير الأفقي في قائمة الملفات |

لا توجد ملاحظة مصنفة «مؤكدة» بصريًا في هذه المرحلة؛ ذلك لا يعني عدم وجود عيوب، بل يعني أن دليل العرض المطلوب غير متاح بعد.

## 5. خط أساس التصوير والاختبار

| المطلوب | الحالة |
|---|---|
| قائمة الملفات، قائمة الموكلين، صفحة الملف، صفحة الموكل | **BLOCKED** — لم يُشغّل التطبيق في متصفح ضمن هذه الجلسة |
| جدول، نموذج، نافذة، الرأس والقوائم المنسدلة | **BLOCKED** — لا توجد لقطات فعلية |
| الثيم الداكن والثيمات الأخرى | **BLOCKED** — لم تُختبر آلية التبديل أو الواجهة |
| المقاسات 360 / 768 / 1024 / 1280 | **BLOCKED** — لا توجد أداة متصفح/لقطات متاحة هنا |
| O15 على جهاز أو متصفح فعلي | **BLOCKED** — يتطلب تشغيلًا فعليًا |
| Console والأخطاء وقت التشغيل | **NOT TESTED** |
| اختبارات الوظائف والتفضيلات القديمة | **NOT TESTED** |
| الأداء وقياس ارتفاعات الصفوف والتمرير الأفقي | **NOT TESTED** |

لم تُنشأ ملفات لقطات فارغة على أنها دليل. يجب وضع اللقطات الفعلية في `docs/design/before/` بعد التقاطها.

## 6. خطة التنفيذ بعد استكمال T0

1. تشغيل التطبيق محليًا والتقاط خط الأساس لكل صفحة ومقاس وثيم متاح.
2. استكمال تتبع الأحداث والتفضيلات لجميع العناصر المجهولة؛ إكمال مصفوفة الوظائف قبل/بعد.
3. إعداد سجل أدوار CSS والمتغيرات مع التحقق من التعريفات المتكررة والاستخدامات الديناميكية، ثم اقتراح تعديلات صغيرة قابلة للرجوع.
4. تنفيذ T1–T3 على دفعات صغيرة واختبارها قبل لمس الصفحات.
5. تنفيذ T4–T9 فقط بعد إثبات التكرار بصريًا ووظيفيًا.
6. استكمال بقية الصفحات والثيمات وإمكانية الوصول، ثم تشغيل الحزمة الشاملة مرة واحدة.
7. كل بند لم يُشغّل يظل `NOT TESTED`، وكل عائق يظل `BLOCKED` مع سببه.

## 7. المخاطر وضوابطها

- **أولوية CSS:** كثرة الملفات المحمّلة تجعل تعديل القواعد العامة خطرًا؛ لا تستخدم `@layer` جماعيًا ولا تحذف قواعد قبل إثبات أثرها.
- **التفضيلات:** توجد إدارة مركزية لتخطيط الأقسام؛ أي تغيير للمعرّفات قد يعطّل تفضيلات سابقة.
- **الجدول:** أدوات الفلترة والتحديد الجماعي والفرز وتخصيص الأعمدة متداخلة؛ تغيير الصف القابل للنقر قد يلتقط أحداث تحديد الصف أو الروابط.
- **المعلومات التشغيلية:** لا تخفِ صفرًا أو حالة فارغة قبل إثبات أنها لا تحمل معنى، ولا تستنتج إجراءً من غياب البيانات.
- **التصوير:** لا يمكن ادعاء تحسن مقاس من دون صور قبل/بعد مأخوذة من البيئة نفسها وبالمقاس والثيم نفسيهما.
